# Руководство по развёртыванию Quasar Bridge: Удалённо и Локально (Standalone)

Данный документ содержит исчерпывающее техническое руководство по двум архитектурным подходам к реализации **Quasar Bridge** для Яндекс Станции Макс (YNDX-0008 / YNDX-00052):
1. **Удалённое развёртывание (External Server Mode)** — мост работает на внешнем домашнем сервере (Linux / Raspberry Pi / x86_64).
2. **Локальное автономное развёртывание (Standalone / On-Device Mode)** — мост скомпилирован под ARM64 и запущен непосредственно на процессоре Станции Макс без необходимости во внешнем сервере.

---

## 1. Архитектура и принцип работы Quasar Bridge

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           Яндекс Станция Макс                               │
│                                                                             │
│  Микрофоны ──► io_device ──► user_config.dat (uniProxyUrl: 8443)            │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
            ┌──────────────────────────┴──────────────────────────┐
            ▼                                                     ▼
┌───────────────────────────────┐             ┌───────────────────────────────┐
│ ВАРИАНТ 1: УДАЛЁННЫЙ СЕРВЕР   │             │ ВАРИАНТ 2: STANDALONE (OD-DEV)│
│                               │             │                               │
│  Внешний Linux-хост (:8443)   │             │  Локальный процесс на Станции │
│  Quasar Bridge Proxy          │             │  127.0.0.1:8443 (/odm/bin)   │
│  ├─ SmartTube Deep Links      │             │  ├─ SmartTube Deep Links      │
│  ├─ Kinopoisk / Zona Engine   │             │  ├─ Kinopoisk / Zona Engine   │
│  ├─ MediaDaemon (:4545)       │             │  ├─ MediaDaemon (:4545)       │
│  └─ LLM Persona Engine        │             │  └─ LLM Persona Engine        │
└───────────────┬───────────────┘             └───────────────┬───────────────┘
                │                                             │
                ▼                                             ▼
┌───────────────────────────────┐             ┌───────────────────────────────┐
│ uniproxy.alice.yandex.net     │             │ uniproxy.alice.yandex.net     │
│ (Официальное облако Яндекс)   │             │ (Официальное облако Яндекс)   │
└───────────────────────────────┘             └───────────────────────────────┘
```

### Принцип подмены голосового потока
Станция взаимодействует с серверами Яндекса через протокол **Uniproxy** (двусторонний WebSocket, передающий Opus-аудио, распознавание речи, директивы и ответы Алисы). 
Адрес сервера зашит в бинарной Protobuf-базе настроек:
`/data/data/com.yandex.io.sdk/databases/user_config.dat`.

С помощью утилиты `station-stream` поле `uniProxyUrl` переписывается с сохранением точной длины (53 байта с пробельным выравниванием), перенаправляя WebSocket-трафик через Quasar Bridge:
- **Удалённый режим:** `ws://<SERVER_IP>:8443/uni.ws`
- **Локальный режим:** `ws://127.0.0.1:8443/uni.ws`

Мост в реальном времени анализирует фразы пользователя:
- Команды для YouTube / фильмов (*«включи на ютубе...»*, *«найди в зоне...»*, *«пауза»*, *«перемотай на 5 минут»*) перехватываются и транслируются в Android Intents и команды MediaDaemon.
- Обычные бытовые запросы (*«какая погода»*, *«поставь таймер»*, музыка) прозрачно проксируются в официальное облако Яндекса без задержек.

## 2. Вариант 1: Удалённое развёртывание (External Server Mode)

В этом сценарии Quasar Bridge работает как systemd-сервис на отдельной машине в локальной сети (сервер, NAS, ПК, Raspberry Pi).

### Преимущества:
- Нулевая нагрузка на процессор и оперативную память Станции.
- Удобство отладки: все логи доступны в `journalctl` на сервере.
- Возможность запуска локальных тяжёлых LLM-моделей на мощностях сервера.

### Системные требования к серверу:
- ОС: Linux (Ubuntu 20.04+, Debian 11+, Arch, Alpine).
- Сеть: Сервер и Станция Макс должны находиться в одной локальной подсети.
- Утилиты: `python3`, `adb`, `git`, `curl`.
- Порт 8443 TCP свободен.

### Пошаговое развёртывание:

#### Шаг 1. Клонирование и деплой
Из корня репозитория выполните скрипт шага 5:
```bash
./scripts/05_deploy_bridge.sh <TARGET_SERVER> <STATION_IP> <SERVER_IP>
```
*Где:*
- `<TARGET_SERVER>` — адрес хоста, куда ставить сервис (`localhost` если ставите прямо на сервер, либо `user@192.168.1.10` для удалённого деплоя по SSH).
- `<STATION_IP>` — IP-адрес Яндекс Станции (например, `192.168.1.50`).
- `<SERVER_IP>` — локальный IP сервера, который виден Станции (например, `192.168.1.1`).

#### Шаг 2. Что делает скрипт автоматически:
1. Клонирует апстрим `quasar-bridge` и накладывает наши патчи из папки `quasar-bridge-patches/`.
2. Компилирует бинарник Go (или использует готовый `binaries/quasar-bridge`).
3. Копирует конфигурацию `/opt/quasar-bridge/config.json` и настраивает адрес ADB (`<STATION_IP>:5555`).
4. Устанавливает и запускает службы systemd:
   - `quasar-bridge.service` — основной прокси-сервер на порту 8443.
   - `adb-station.service` — постоянное авто-поддержание ADB-коннекта к Станции.
5. Вызывает `station-stream bridge <STATION_IP> <SERVER_IP>`, переключая аудиопоток Станции на сервер.

#### Шаг 3. Проверка статуса и логи
На сервере:
```bash
# Статус сервиса
systemctl status quasar-bridge

# Чтение логов в реальном времени
journalctl -u quasar-bridge -f

# Проверка слушающего порта
ss -tlpn | grep 8443
```

## 3. Вариант 2: Локальное автономное развёртывание (Standalone / On-Device Mode)

В этом сценарии Quasar Bridge скомпилирован под целевую архитектуру ARM64 (Linux aarch64) и работает **прямо на самой Станции Макс**. Дополнительные компьютеры или серверы не требуются — колонка полностью автономна!

### Преимущества:
- **Полная автономность:** умный дом, голосовое управление YouTube, Zona и кастомные команды работают даже если домашний сервер выключен.
- **Минимальная задержка (Zero Network Hop):** медиакоманды передаются через петлевой интерфейс (`127.0.0.1`), без передачи пакетов по Wi-Fi между Станцией и сервером.
- **Отказоустойчивость:** колонка не зависит от стабильности внешних служб или локального роутера.

### Архитектурные особенности на Android TV 9:
- Бинарник: `/odm/bin/quasar-bridge` (ARM64 ELF, static/musl).
- Конфигурация: `/data/quasar-bridge/config.json`.
- Переменные окружения и ключи: `/data/quasar-bridge/runtime.env` и `/data/quasar-bridge/llm.json`.
- Автозапуск: `/odm/bin/start-quasar.sh`, интегрированный в цепочку загрузки `/odm/bin/start-dropbear.sh`.
- Сторожевой флаг: `/data/quasar-bridge/enabled` (наличие файла разрешает запуск службы при загрузке Станции).

### Пошаговое развёртывание (в одну команду):

Из корня репозитория запустите:
```bash
./scripts/deploy_standalone.sh <STATION_IP>
```
*(Если IP не передан, скрипт автоматически использует IP из файла `.station_env`)*.

#### Что происходит в процессе:
1. **Проверка окружения:** скрипт подключается к Станции по SSH (:2222), проверяет Permissive SELinux и доступность `/odm`.
2. **DNS & Сертификаты:** настраиваются надежные DNS (`77.88.8.8`, `1.1.1.1`) в `/data/dropbear/etc/resolv.conf`.
3. **Заморозка OTA:** отключается системный апдейтер `com.yandex.launcher.updaterapp`, гарантируя несменяемость прошивки.
4. **Установка бинарника:** `binaries/quasar-bridge-arm64` заливается в `/odm/bin/quasar-bridge` с правами `755` и контекстом `u:object_r:adbd_exec:s0`.
5. **Конфигурация:** устанавливается автономный конфиг `configs/quasar-bridge/config.standalone.json`, где адрес ADB выставлен на локальный loopback `127.0.0.1:5555`.
6. **Запуск:** стартует фоновый процесс на порту 8443, ожидается готовность сокета.
7. **Перенаправление потока:** вызывается `station-stream.py bridge <STATION_IP> 127.0.0.1`, направляя Алису на саму себя.

#### Мониторинг на Станции:
```bash
# Подключение к станции
ssh -p 2222 root@<STATION_IP>

# Проверка процесса
pgrep -fl quasar-bridge

# Просмотр лога работы
tail -f /data/quasar-bridge/bridge.log
```

## 4. Мгновенное переключение и откат (Rollback)

В проекте реализована система бесшовного переключения между режимами без необходимости перезагрузки колонки.

### Откат из Standalone обратно на внешний сервер:
Если вы хотите вернуть обработку на внешний сервер:
```bash
./scripts/rollback_standalone.sh <STATION_IP> <SERVER_IP>
```
Скрипт:
1. Удалит sentinel-файл `/data/quasar-bridge/enabled` и остановит локальный процесс `quasar-bridge` на Станции.
2. Проверит и перезапустит сервис `quasar-bridge` на сервере `<SERVER_IP>`.
3. Переключит аудиопоток колонки на IP сервера: `ws://<SERVER_IP>:8443/uni.ws`.

### Возврат на официальное облако Яндекса:
Если требуется временно или полностью отключить Quasar Bridge и вернуть Станцию в заводской режим работы с облаком Яндекс:
```bash
python3 scripts/station-stream.py yandex <STATION_IP>
```

### Проверка текущего режима Станции:
```bash
python3 scripts/station-stream.py status <STATION_IP>
```
*Пример вывода:*
```text
[*] Checking stream configuration for 192.168.1.50...
[+] Active Stream: Quasar Bridge (ws://127.0.0.1:8443/uni.ws)
```

## 5. Сравнительная таблица: Remote vs Standalone

| Параметр | Вариант 1: Remote (Сервер) | Вариант 2: Standalone (На Станции) |
|---|---|---|
| **Хост выполнения** | Внешний Linux-ПК / Сервер | Amlogic S905X2 (на Станции) |
| **Порт сервиса** | `<SERVER_IP>:8443` | `127.0.0.1:8443` |
| **Потребление RAM** | ~35 MB на сервере | ~30 MB в RAM Станции (из 2 GB) |
| **Потребление CPU Станции** | 0% | 0.5–2% в момент запроса |
| **Задержка медиа-команд** | ~120–180 мс (зависит от Wi-Fi) | **~35–50 мс (мгновенно)** |
| **Зависимость от сервера** | Да (при отключении ПК мост падает) | **Нет (100% автономно)** |
| **Тяжёлые локальные LLM** | Да (можно подключить Ollama/vLLM) | Через внешние API (OpenAI/Groq/Grok) |
| **Логирование** | `journalctl -u quasar-bridge` | `/data/quasar-bridge/bridge.log` |
| **Автозапуск** | Systemd unit на сервере | `/odm/bin/start-quasar.sh` |

## 6. Диагностика и устранение неисправностей (Troubleshooting)

### 1. Колонка перестала реагировать на голос после перезагрузки
- **Причина:** SELinux вернулся в `Enforcing` (холодный старт ядра).
- **Решение:** Дождитесь отработки `fix-enforce.sh` (10–15 сек). Проверьте статус:
  ```bash
  ssh -p 2222 root@<STATION_IP> "cat /sys/fs/selinux/enforce"
  ```
  Если возвращает `1`: выполните `/odm/bin/fix-enforce.sh`.

### 2. Запрос к Алисе уходит в официальный Яндекс, минуя SmartTube
- **Причина:** Станция обновила кэш настроек или упал процесс моста.
- **Решение:**
  1. Проверьте статус: `python3 scripts/station-stream.py status <STATION_IP>`.
  2. Если поток сброшен, перезапустите:
     - Для Standalone: `./scripts/deploy_standalone.sh <STATION_IP>`
     - Для Remote: `python3 scripts/station-stream.py bridge <STATION_IP> <SERVER_IP>`

### 3. Ошибка соединения с MediaDaemon (:4545)
- **Симптом:** Видео в SmartTube запускается, но пауза или перемотка по таймкоду не работают.
- **Решение:** Проверьте, запущен ли демон в памяти:
  ```bash
  ssh -p 2222 root@<STATION_IP> "toybox netstat -tlpn | grep 4545"
  ```
  Если порт закрыт: выполните `/odm/bin/start-mediadaemon.sh`.
